# 第 0 阶段原型说明与评审脚本

## 1. 原型范围

可点击原型位于 [prototype/stage-0/index.html](../../prototype/stage-0/index.html)，覆盖以下视图：

1. 首页搜索与语音入口。
2. 搜索结果、语言识别、领域筛选和匹配类型。
3. 概念详情、三语术语、定义、例句、来源和关联概念。
4. 管理端多语概念编辑与质量提示。
5. UniApp 手机端的核心查询布局预览。
6. 参考成熟在线词典信息层级的多义词页面：词头、发音、收藏、义项导航、分场景定义、例句、相关词和短语。

该原型用于需求和信息架构评审，不连接后端，不代表最终视觉品牌。V1.1 已纳入产品和术语审核意见。

## 2. 交互说明

- 在首页输入 `人工智能`、`inteligencia artificial`、`artificial intelligence`、`机器学习`、`cadena de suministro` 等样例可得到匹配结果。
- 点击结果卡片进入概念详情。
- 顶部导航可直接切换首页、结果、详情、管理端和移动端预览。
- “语音查询”展示授权与识别流程提示，不实际调用麦克风。
- 管理端可切换中文、西班牙语和英语编辑标签，并展示必填与质量规则。
- “多义词”视图使用西班牙语 `modelo` 演示科研模型、产品型号和时尚模特三个独立义项。
- 页面宽度小于 760 px 时自动切换为移动布局。

## 3. 评审任务

### 任务 A：三语查询

1. 从首页分别输入三种语言的“人工智能”。
2. 确认系统是否清楚展示识别语言、命中原因、领域和三语对译。
3. 确认用户是否能在一次点击内进入详情。

预期：三种查询均落到同一概念 `IT-000001`。

### 任务 B：同形异义和领域筛选

1. 进入搜索结果页。
2. 观察领域筛选、词性和地区入口。
3. 评估当同一词形有多个义项时，领域与定义摘要是否足以区分。

预期：结果卡必须始终显示领域和定义摘要，不能只展示译词。

### 任务 C：术语证据

1. 打开概念详情。
2. 查找术语类型、发音、定义来源和相关概念。
3. 评估“纠错/建议”入口是否容易发现但不过度干扰阅读。

预期：用户可判断术语是否首选、来源是什么、相关知识在哪里。

### 任务 D：编辑与审核准备

1. 打开管理端视图。
2. 依次查看三种语言字段。
3. 检查领域、来源、关系、版本状态和质量提示位置。

预期：编辑能在提交前发现缺少首选词、定义或来源的问题。

### 任务 E：手机端

1. 打开移动端预览或缩小浏览器宽度。
2. 完成输入、查看结果、进入详情和收藏的路径评估。
3. 检查语音按钮是否容易触达且不会误触。

### 任务 F：多义词分场景解释

1. 打开“多义词”视图，查询词为西班牙语 `modelo`。
2. 使用义项导航分别查看科研与计算、工业产品、时尚与展示三个场景。
3. 检查每个义项的中文和英语对译、定义、例句、领域及相关词是否彼此独立。
4. 检查词头发音、收藏、复制和反馈入口是否符合常见在线词典的使用习惯。

预期：用户能清楚判断三个意义的适用场景，不会把“模型”“型号”和“模特”理解为同一概念。

## 4. 评审记录字段

每条意见应记录：编号、评审人角色、视图、任务步骤、观察、严重级别、建议、关联需求编号和处理结论。严重级别采用：阻断、严重、一般、建议。

## 5. 通过标准

- 6 个评审任务均可在无口头指导下完成。
- 不存在阻断级问题。
- 用户能理解系统以“概念”为核心，而非逐词机器翻译。
- 术语负责人确认详情字段足以支撑专业判断。
- 编辑和审核角色确认关键证据与状态不会被隐藏。
- 移动端核心路径不依赖悬停或桌面宽屏交互。

## 6. 下一轮原型输入

评审通过后，第 1 阶段应补充视觉品牌、登录注册、无结果、错误、加载、权限不足、批量导入和审核差异视图，并将信息架构转换为前端路由和组件清单。
